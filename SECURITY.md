# Security Policy

## Reporting a Vulnerability

Report suspected vulnerabilities privately using
[GitHub's private vulnerability reporting form](https://github.com/peteallport/macflare/security/advisories/new).
Include the affected commit or version, reproduction steps, expected and actual
behavior, and potential impact. Use synthetic account data and redact credentials,
account identifiers, and personal information.

Do not disclose an unresolved vulnerability or sensitive reproduction details in a
public issue or pull request. If a credential has been exposed, revoke or rotate
it before sharing further details. Deleting a file does not remove it from Git
history, forks, or caches.

Macflare is under active development. Reports against current `main` are welcome;
there is no guaranteed response time or support window for older snapshots.

## Contributor Review

All contributor changes require a pull request and approval from `@peteallport`.
The repository-wide [CODEOWNERS](.github/CODEOWNERS) entry includes this policy,
workflows, and the ownership file itself. See
[Contributing](CONTRIBUTING.md#quality-and-public-content-policy) for the review,
CI, direct-push exception, and workflow permission policy.
